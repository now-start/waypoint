# AI 브리핑 설계

## 1. 목적

AI 브리핑은 서버가 계산한 운영현황과 이상징후를 운영자가 바로 읽을 수 있는 문장으로 바꾸는 기능이다.

AI는 이상 여부를 직접 판단하지 않는다. 판단은 서버 계산 로직이 수행하고, AI는 근거를 빠뜨리지 않는 요약과 표현을 담당한다.

## 2. MVP 범위

포함:

- 현재 이상징후 요약
- 우선 확인 노선 정리
- 영향 구간 또는 정류소 설명
- 근거 지표 기반 운영 문장 생성
- 이상징후 임계값 튜닝 후보 보고

제외:

- 민원 답변 초안
- 자연어 검색 필터 생성
- 운영 보고서 파일 생성
- 원인 확정
- 배차 조치 추천
- 임계값 자동 변경

## 3. 입력 데이터

AI 입력은 자유 텍스트가 아니라 서버가 만든 구조화 데이터다.

입력 후보:

```json

  "generatedAt": "2026-06-12T09:00:00+09:00",
  "city": "창원시",
  "period": {
    "start": "2026-06-12T08:30:00+09:00",
    "end": "2026-06-12T09:00:00+09:00"
  },
  "summary": {
    "observedRouteCount": 42,
    "normalRouteCount": 35,
    "cautionRouteCount": 5,
    "warningRouteCount": 2
  },
  "anomalies": [
    {
      "type": "HEADWAY_TOO_WIDE",
      "severity": "WARNING",
      "routeNo": "101",
      "direction": "창원역 방면",
      "area": "창원역-시청 구간",
      "observedAt": "2026-06-12T08:45:00+09:00",
      "metricName": "maxHeadwayMinutes",
      "metricValue": 24,
      "thresholdValue": 15,
      "evidence": "후속 차량 위치가 5개 정류장 뒤로 관측됨"
    }
  ],
  "thresholdReview": [
    {
      "metricName": "maxHeadwayMinutes",
      "currentThresholdValue": 15,
      "observedP50": 8,
      "observedP90": 14,

      "alertCount": 12,
      "falsePositiveCandidateCount": 5,
      "reviewPoint": "출근 시간대 정상 분포 상단과 기준값이 가까워 주의 알림이 잦을 수 있음"
    }
  ]
}
```

## 4. 출력 형식

AI 출력은 다음 구조를 따른다.

```json
{
  "headline": "현재 2개 노선에서 우선 확인이 필요합니다.",
  "briefing": "101번은 창원역 방면에서 차량 간격이 기준보다 크게 벌어진 상태입니다...",
  "checkpoints": [
    "101번 창원역-시청 구간 차량 간격 확인",
    "최근 위치 갱신이 지연된 차량 여부 확인"
  ],
  "tuningPoints": [
    {
      "metricName": "maxHeadwayMinutes",
      "summary": "출근 시간대 기준값이 정상 분포 상단과 가까워 주의 알림이 반복될 수 있습니다.",
      "evidence": "최근 7일 P90 14분, P95 18분, 현재 기준 15분",
      "recommendation": "기준값 조정 여부를 실측 데이터와 함께 검토하세요."
    }
  ]
}
```

화면에는 JSON을 그대로 보여주지 않고 다음 영역으로 렌더링한다.

- 한 줄 요약
- 상세 브리핑
- 확인 필요 사항
- 임계값 튜닝 포인트
- 근거 이상징후 목록

## 5. 표현 규칙

해야 할 표현:

- "데이터상 관찰됩니다"
- "가능성이 있습니다"
- "확인이 필요합니다"
- "기준보다 높습니다"
- "최근 수집 기준입니다"
- "기준값 조정 검토 대상입니다"

피해야 할 표현:

- "원인은 사고입니다"
- "배차 누락이 확실합니다"
- "운전자가 지연했습니다"
- "민원 책임이 있습니다"
- "즉시 조치해야 합니다"
- "기준값을 변경했습니다"

## 6. 시스템 프롬프트 초안

```text
당신은 창원시 버스 운영 데이터를 요약하는 업무 보조자입니다.
입력으로 제공된 서버 계산 결과만 사용해 운영자용 브리핑을 작성하세요.
입력에 없는 사실, 원인, 책임 소재를 추측하지 마세요.
원인은 확정하지 말고 가능성 또는 확인 필요 사항으로 표현하세요.
브리핑은 간결하게 작성하고, 노선번호, 영향 구간, 근거 지표를 빠뜨리지 마세요.
임계값 튜닝 포인트는 데이터 분포와 현재 기준의 차이를 설명하는 검토 의견으로만 작성하세요.
임계값을 자동으로 변경했거나 변경해야 한다고 단정하지 마세요.
```

## 7. 사용자 프롬프트 초안

```text
다음 운영현황과 이상징후를 기준으로 운영자용 브리핑을 작성하세요.

요구사항:
- JSON만 반환
- 마크다운, 설명 문장, 코드블록 금지
- `headline`, `briefing`, `checkpoints`, `tuningPoints` 키만 사용
- 한 줄 요약 1개
- 상세 브리핑 2-4문장
- 확인 필요 사항 최대 5개
- 임계값 튜닝 포인트 최대 3개
- 확정 원인 단정 금지
- 임계값 자동 변경 표현 금지

입력:
{{briefingInputJson}}
```

## 8. 실패 처리

AI 호출 실패 시:

- 이상징후 목록은 그대로 보여준다.
- 브리핑 영역에는 생성 실패 상태를 표시한다.
- 실패 메시지는 내부 로그에 남긴다.
- 사용자는 다시 생성할 수 있다.

AI 출력 파싱 실패 시:

- 원문을 바로 노출하지 않는다.
- 재시도 또는 실패 상태로 처리한다.
- 입력 스냅샷과 모델 응답 일부를 디버그 로그로 남긴다.

## 9. 품질 기준

- 서버 입력에 있는 주요 이상징후를 누락하지 않는다.
- 노선번호와 영향 구간을 포함한다.
- 근거 지표를 최소 1개 이상 포함한다.
- 임계값 튜닝 포인트는 현재 기준값, 관측 분포, 알림 빈도 중 최소 1개 이상을 근거로 제시한다.
- 확정 원인과 책임 소재를 말하지 않는다.
- 운영자가 30초 안에 현재 확인 우선순위를 이해할 수 있다.

저장 시에는 검증된 JSON 전체를 `ai_briefing.output_json`에 보관한다.

## 10. 미정 사항

- 모델별 최대 입력 길이
- 브리핑 재생성 횟수 제한
- 프롬프트 버전 관리 방식

## 11. 설정

- Ollama endpoint는 `OLLAMA_BASE_URL` 환경변수로 관리한다.
- `OLLAMA_BASE_URL` 기본값은 `http://localhost:11434`로 한다.
- Ollama 모델은 `OLLAMA_MODEL` 환경변수로 관리한다.
- `OLLAMA_MODEL` 기본값은 `llama3.1`로 한다.
