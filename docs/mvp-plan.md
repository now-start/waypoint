# MVP 구현 계획

## 1. 목적

MVP는 창원시 버스 운영 데이터를 수집하고, 운영현황과 이상징후를 계산한 뒤, AI 브리핑으로 요약하는 최소 업무 콘솔을 만든다.

범위는 운영현황, 이상징후, AI 브리핑까지다. 민원 검증, 자연어 검색 필터, 별도 데이터 상태 화면, 권한 구분은 MVP 이후로 미룬다.

## 2. 개발 순서

### 2.1 로컬 실행 기반과 패키지 구조

- `local` 프로필로 애플리케이션을 실행한다.
- 로컬에서는 H2 `MODE=MariaDB`를 사용한다.
- 운영 DB는 MariaDB를 기준으로 한다.
- OTEL은 MVP 개발 중 기본 비활성화 상태로 둔다.
- TAGO 인증키는 `TAGO_SERVICE_KEY` 환경변수로 주입한다.
- Ollama endpoint는 `OLLAMA_BASE_URL` 환경변수로 주입하고 기본값은 `http://localhost:11434`로 둔다.
- Ollama 모델은 `OLLAMA_MODEL` 환경변수로 주입하고 기본값은 `llama3.1`로 둔다.
- 이상징후 임계값은 설정값으로 분리한다.
- 패키지는 `domain`, `application`, `adapter`, `config` 기준으로 만든다.
- 최상위 `controller`, `service`, `repository`, `data` 같은 단순 계층 패키지는 새로 만들지 않는다.

완료 기준:

- `./gradlew test`가 성공한다.
- `./gradlew bootRun --args='--spring.profiles.active=local'`로 앱이 실행된다.
- `docs/architecture.md`의 클린 아키텍처 패키지 규칙과 충돌하지 않는다.

### 2.2 기준 데이터 수집

- TAGO 도시코드 목록에서 창원시 도시코드를 확정한다.
- 창원시 전체 노선 목록을 수집한다.
- 창원시 전체 노선의 노선별 경유 정류소를 수집한다.
- 정류소 기본 정보를 저장한다.

완료 기준:

- 창원시 전체 노선과 경유 정류소를 데이터베이스에서 조회할 수 있다.
- 수집 시각과 원본 응답 추적 정보가 남는다.

### 2.3 실시간 데이터 수집

- 창원시 전체 노선의 버스 위치정보를 주기적으로 수집한다.
- 도착정보는 전체 노선 운영현황 보조용 관찰 대상 정류소를 정해 주기적으로 수집하고, 수신 여부와 최근성을 확인한다.
- 수집 실패와 빈 응답은 별도 상태로 기록한다.

완료 기준:

- 최근 위치정보와 도착정보를 화면/API에서 조회할 수 있다.
- 동일 데이터 중복 저장을 최소화한다.

### 2.4 운영현황 계산

- 노선별 최근 위치 갱신 시각을 계산한다.
- 노선별 운행 차량 수를 계산한다.
- 노선별 차량 간격 상태를 계산한다.
- 상태를 정상, 주의, 이상으로 분류한다.

완료 기준:

- 운영현황 화면에 노선별 상태가 표시된다.
- 상태 판단 근거 값이 함께 표시된다.

### 2.5 이상징후 계산

- 차량 간격 벌어짐을 탐지한다.
- 차량 간격 붙음을 탐지한다.
- 위치 갱신 지연을 탐지한다.
- 도착 예정 시간 변동 탐지는 TAGO 응답 필드 확인 후 확장 범위로 둔다.

완료 기준:

- 이상징후 화면에 탐지 결과가 시간순 또는 심각도순으로 표시된다.
- 각 이상징후는 노선, 방향 또는 구간, 발생 시각, 근거 지표를 가진다.

### 2.6 AI 브리핑

- 이상징후 계산 결과를 구조화된 입력으로 만든다.
- Ollama에 브리핑 생성을 요청한다.
- 생성된 브리핑과 입력 근거를 함께 저장한다.
- 누적 수집 데이터 기준으로 임계값 튜닝 후보를 브리핑에 함께 포함한다.
- 브리핑 실패 시 서버 계산 결과는 그대로 보여준다.

완료 기준:

- 운영자는 AI 브리핑을 생성하고 다시 조회할 수 있다.
- 운영자는 현재 임계값이 민감하거나 둔감한 후보와 그 근거 분포를 확인할 수 있다.
- 브리핑 문장은 확정 원인을 단정하지 않는다.

## 3. MVP 제외 범위

- 로그인, 사용자, 권한 구분
- 민원 검증 및 답변 초안
- 자연어 검색 필터
- 별도 데이터 상태 화면
- 도착 예정 시간 변동 기반 이상징후
- 관리자 설정 화면
- 배차 최적화
- 지도 기반 시각화
- 운영 보고서 파일 생성

## 4. 위험과 대응

### TAGO 응답 품질

공공 API는 빈 응답, 지연, 필드 누락 가능성이 있다.

대응:

- 원본 응답 상태를 기록한다.
- 계산 로직은 빈 응답을 정상 데이터로 오해하지 않는다.
- 화면에는 마지막 수집 시각을 표시한다.

### AI 출력 신뢰성

AI는 원인과 책임을 단정할 수 있다.

대응:

- 입력을 서버 계산 결과로 제한한다.
- 프롬프트에 확정 표현 금지를 넣는다.
- 화면에는 근거 지표를 브리핑과 함께 표시한다.

### 화면 범위 확장

민원, 검색, 데이터 상태까지 한 번에 넣으면 MVP가 커진다.

대응:

- 첫 버전 화면은 통합 대시보드 하나에 운영현황, 이상징후, AI 브리핑을 배치한다.
- 나머지는 PRD의 향후 확장 항목으로 관리한다.

## 5. 1차 완료 정의

- 창원시 전체 노선 기준 데이터가 저장된다.
- 창원시 전체 노선 위치정보와 운영현황 보조용 관찰 대상 정류소 도착정보를 수집한다.
- 운영현황과 이상징후가 계산된다.
- AI 브리핑을 생성하고 화면에서 확인한다.
- 로컬 실행과 기본 빌드가 재현된다.
